fix(commercial): 收口 Mirror 与评理的实战缺陷，补齐接口层用例

上一提交（44ed92e）之后，Mirror 与评理两个域在真实链路复验中又暴露了几个只有
跑起来才看得见的问题，一并修掉；测试从 59 条扩到 64 条。

评理
- DisputeCase 上没有 character 关系，只有 characterId 字段。原查询写
  select: {character: ...} 在运行时直接报 Unknown field character，
  改为按 characterId 单独取名字。
- snapshotOf 从「只认 version === 1」改为走 isDisputeRules 全字段校验，
  坏快照走默认规则而不是把缺字段的对象当规则用。
- 到期与结案拆成两条提示：到截止时间不再笼统报「正在结案」。
- 新增第 10 条用例：直接压 6 个 route handler 串完发起 → 详情 → 投票 → 撤回，
  覆盖 201/200/401/403/404 与 options、excerpt。

Mirror
- MirrorGenerationError 改为继承 MirrorError。此前题数/字数不合法抛的是
  普通 Error，路由映射不到 400，用户看到的是 500。
- overLimitPolicy=CHARGE 不再在未超额时也直接 429：只在额度真正用尽时按策略提示。
- 匿名额度补齐「浏览器回传用量」通道：Cookie 一路取服务端记忆与浏览器回报次数的
  较大者，进程重启后当日额度不会复活。
- IP 盐不再退化成公开常量：MIRROR_IP_SALT 未配置时复用 JWT_SECRET（生产强制存在），
  否则 IPv4 加盐哈希可被彩虹表反推。.env.example 补 MIRROR_IP_SALT 与
  MIRROR_ATTRIBUTION_SECRET 的说明与改动影响。
- 登录用户看自己的分享链接看不到删除按钮：本仓库登录态只在 localStorage 存 Bearer，
  服务端渲染拿不到。新增 mirror-result-loader：服务端先渲染公开视图，客户端拿到
  token 后请求接口升级为本人视图（带三题原回答与删除）。
- GET /api/mirror 不再把 cookies 字段回给浏览器。
- 清掉 mirror 内死代码：mirrorShareText、MIRROR_PUBLIC_KEYS、extractJsonText 导出、
  model-call 的重复 re-export、toMirrorError 里已不可达的分支。
- 测试 14 → 18 条，新增接口层：初始化签发 HttpOnly 主体 Cookie 且不回显 IP、
  同 IP 超限 POST 返回 429 且未产生任何 AiCall（证明额度检查在模型调用之前）、
  题数错误返回 400 且不消耗额度、share/mine/compare 的可见性与 401/403。

验证：npx tsc --noEmit 0 错误；npm run test:commercial 64/64；
npm run test:mirror:generation 18/18；npm run verify:build 成功。
