### 顺手修掉一个自己埋的坑（矩阵）

`scripts/run-browser-matrix.mjs` 支持「直接传文件路径」。原实现对 `.ts/.tsx` 走 tsx、`.mjs/.js` 走裸 node，
结果跑 `node scripts/verify-*-browser.mjs` 报 `Cannot find package '@/lib' imported from src/lib/db.ts`——
因为这些脚本顺着 import 链会读到 TypeScript，`@/` 别名只有 tsx 能解析。已改为：只要是文件路径就统一
`node --import tsx <file>`（和 package.json 里这些脚本自身的调用方式一致）。

**记住：矩阵传「文件路径」和传「脚本名」是两条路径**，传脚本名会取 package.json 的命令行

所以 HTTP 主套件要写 `node scripts/run-browser-matrix.mjs tests/runner.ts`。

改完 15 个后台栏目后逐条重跑 `scripts/verify-*-browser.mjs`。**失败看着重复，其实是逐层解 mask**：

   `财务对账与 AI 成本→订单与退款`、`注册合规要求→注册确认要求`。
2. **DOM 结构变了**（改脚本 + 补 `aria-label`）：`window.confirm`→后台 Dialog；status 提示条→AdminPanel 标题+列表；
   `section[aria-labelledby=...]`/`section[aria-label=...]` 这类旧 CSS 选择器→按 role=region 定位
   （已给这些 AdminPanel 补 `aria-label`：`模型价格历史`/`平台任务`/`连续签到金币`/`礼物目录`/
   `运维告警`/`支付回调异常（聚合）`/`用户详情`/`角色管理预览`）。
3. **我自己引入的真实回归**（改组件，不是脚本问题）：
   - `finance-packages.tsx`：`AdminNotice` 顶掉了 `DataTable`，保存成功后整套列表消失。已改为常驻表格。
   - `ai-model-management.tsx`：**漏了「操作理由」必填字段**，API 侧 `reason()` 必填，保存被 HTML5 required 拦死。
     教训：`<Select>`/`<Input>` 换成 UI 组件时别把必填项整块丢掉。
   - **`<label>` 里不能塞说明文字**：`label` 的 textContent 就是控件可访问名，
     把 hint span 放进去会污染名字（`API 基础地址`/`逻辑模型标识` 的 `exact` 匹配全部失效）。已移到 `<label>` 外面。
   - **`<select>` 包在 `<label>` 里，option 文本会拼进可访问名**：`getByLabel('供应商选择',{exact:true})` 拿不到。
     凡是包进 label 的 `<Select>` 都要显式写 `aria-label`（已补：供应商选择/环境/模型/账号状态/社区权限/排序/
     评论状态/帖子状态/订单状态/任务分类/核验条件/重复周期/内容编辑器各下拉）。
   - 同一页多个面板都有「操作理由」时，脚本用 `.first()/.last()` 猜 DOM 顺序是错的 —— 必须按 panel region 取。

## 开源竞品调研（结论，供后续定位/找轮子用）

核过 GitHub API 的真实星数（2026-10-19）：Open-WebUI 156k、Dify 158.9k、NextChat 88.9k、
LobeHub 83.3k、Cherry Studio 52.7k、LibreChat 46.0k（MIT）、Jan 45.0k、SillyTavern 34.7k（AGPL）、
FastGPT 29.9k、assistant-ui 12.6k（MIT）、RisuAI 1.7k、PocketRisu 404、Agnai 788（2026-06 后停更）。

- **结论：没有同构开源项目**。「角色对话 + UGC 社区 + 金币/支付 + 运营后台 + 多语种」这五项没被任何开源项目拼在一起，
  右上象限是空的；能对标的只有闭源（Character.AI / 星野 / Talkie / JanitorAI / Chub）。
- 结构最接近的骨架是 `PocketRisu`（Risu 的服务端分叉，最小可读 RP SaaS）与 `Agnai`（唯一以 multi-user+scale 设计）。
- **许可证红线（重要）**：SillyTavern AGPL-3.0、RisuAI/Cherry Studio GPL-3.0 → 代码贴进闭源商业项目即触发全项目开源；
  LobeHub 是 Community License（做衍生作品需商业授权）；Open WebUI 禁止 50 用户以上改品牌标识。
  唯一能直接抄代码的是 LibreChat（MIT）与 assistant-ui（MIT）。
- 可借鉴的具体点：SillyTavern 的角色卡/世界书（PNG tEXt character-card V2 是事实标准，别自造格式）、
  RisuAI 的变量与分支存档、LobeHub 对话页信息架构与移动端、LibreChat 多 provider 设置页与 RBAC 后台。

### 技术栈核对（决定能不能搬）

- **LobeHub**：Next ~16.3.8 + React 19.2.7 + zustand + drizzle-orm + 自有 `@lobehub/ui`。
  与本项目（Next 15.5 + React 19 + Prisma）同构度最高，但 LobeHub Community License 禁止未授权做衍生作品 → 只能读着重写。
- **LibreChat**：client 是 **Vite + React SPA**（Radix/Ariakit/Monaco/Sandpack），api 是 **Express 5 + MongoDB/Mongoose**。
  MIT 可复制，但后端整体不可移植（Mongo→Prisma 等于重写），前端也要从 SPA 改成 App Router。
  可搬的是 `client/src/components/{Chat,Chat/Input,SidePanel,Nav}` 与 Auth/Admin 的交互与结构。
- **Open WebUI**：SvelteKit + Python，前端零复用，只看后台 RBAC 设计。
- 结论口径：**壳子（登录/会话/消息流/后台/provider 配置）抄 LibreChat（MIT），皮与信息架构学 LobeHub。**

### 上一轮评审的三处错误（用户反驳后逐条复核，已确认是我说错）

1. **耦合位置判断错**。`chat-stream.ts` 头部自述与代码一致：只做提示词构造、模型回退链、SSE 协议输出，
   **不含** `reserveAiCall` / `checkRateLimit` / 任何 db 写。编排全在
   `api/conversations/[id]/messages/route.ts` POST（鉴权→限流→预留额度→存用户消息→生成→存回复→结算）。
   且 `messages/[messageId]/regenerate/route.ts` 是**第二份同构编排**（两文件各 7 处同名调用）。
   → 真正的缺口是「路由编排层重复」，不是「流式层强耦合」；正解是抽一次回合的聊天应用服务，两调用方复用。
2. **成本章不是"只有公式"**。表 21 已有 0.954 元/章、954 元/天（20 回合 × 6000 输入/400 输出 + 每百万 5/15 元 + 20% 波动）。
   真正缺口是**真实单价缺失**：本地 `prisma/.local/dev.db` 的 `ai_models`/`ai_model_prices` 均 0 行，
   `.env` 里 `AI_INPUT_PRICE_PER_MILLION=""`、`AI_OUTPUT_PRICE_PER_MILLION=""`、`AI_PRICE_MODEL="gpt-6-luna"`、`AI_PRICE_CURRENCY="USD"`。
   统一场景（20 回合 × 8000/300）= 16 万输入 + 6000 输出 → **每章 = 0.16P + 0.006Q**。
3. **工期"×1.5"是拍脑袋**。`run-browser-matrix.mjs` 的 DEFAULT_MATRIX 是 10 个浏览器任务 + `stress:economy`，
   不是"160 项 HTTP + 16 套、一轮一小时"的强制门禁；测试范围应按影响面定。
   正确做法是把开发/联调迁移/验证与故障演练/返工缓冲四类分开重列，给区间。

#### 编辑器坐标的两个硬坑（下次直接用）

1. **不要用段落的 `end_index` 作为插入点**：那里的位置在段落标记之内，`## 标题` 会把**前一段正文吞进标题**（实测把第 29 章末段整段变成了 Heading 2）。
2. 正确做法：取**下一个节点（通常是下章 Heading1）的 `start_index`** 作为插入点，属于块边界，不拆段。
3. 插错用 `doc_undo_ai_edit target_version=<v>`（先 `doc_list_recent_ai_edits` 取 version），是 git-revert 语义，会写新 revision，可再撤。
4. `doc_insert_markdown` 的 `markdown` 支持 `file://<绝对路径>`，长内容一律走文件，避免命令行转义。
