## 结果与范围

- `npm run db:backup -- <标签>` 按 DATABASE_URL 选择源库，以 VACUUM INTO 保存包含已提交 WAL 的单文件快照。
- 完整性、外键、迁移状态和各表计数取自备份快照。修正旧工具从运行源库统计计数、只输出少量表及泰语提示的问题。
- `npm run db:restore -- <备份文件> <全新目标文件>` 先检查备份，再独占创建目标并复验，不覆盖数据库或残留附属文件。不自动修改环境配置或停止、切换服务。
- 空文件、损坏文件、缺失迁移历史、未完成迁移均不报告成功。备份源未找到时不创建空源库；恢复只接受单文件快照。
- 基础设施职责在 `src/lib/operations/sqlite-backup.mjs`，两个 scripts 负责参数和输出，没有改动业务路由、schema、支付或用户余额。

## 数据库与上传文件联合恢复（2026-10-13）

先停止所有业务写入与文件清理任务，再运行 `npm run state:backup -- <标签>`。输出目录位于 `prisma/backups/`，包含数据库快照、上传文件与完整性清单。数据库快照自身一致，但数据库和文件不是一个原子事务，因此不承诺在线联合备份；引用缺失、嵌套目录和符号链接会使备份失败。失败时保留新目录以供检查，重试另取标签。

运行 `npm run state:restore -- <备份目录> <全新恢复目录>`；先核验清单、数据库及文件，再独占创建目标，不覆盖原库或上传目录。恢复后同时配置 `DATABASE_URL` 指向目标 `database.db`、`UPLOADS_DIRECTORY` 指向目标 `uploads`，人工更换 JWT 密钥，再启动服务。默认上传位置仍是 `public/uploads`。恢复目录中的清单记录恢复时间点，业务重新写入后不能当作未改动的备份再校验。

备份含私人聊天、账户、支付及上传数据，需限制访问并使用受保护的异地存储。清单的 SHA256 检测损坏，不证明来源可信；仅从受控备份恢复。工具不复制项目根目录的 `.env` 或自动保管/轮换密钥；密钥与部署配置另行受保护保管。

隔离测试 `test:m5:state-backup` 7/7：15 条有序迁移、WAL 最新提交、余额和聊天恢复、上传归属与旧图片保留、重复目标拒绝、篡改/非法路径/引用缺失拒绝，以及自定义上传位置的保存、读取、帖子校验和注销清理。原备份 6/6、注销 9/9、类型与当时主项目生产构建也通过。
