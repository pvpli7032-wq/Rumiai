## 实现与边界

- `/finance` 与 `/api/finance/report` 提供只读财务看板。独立 `PAYMENT_ADMIN_USER_IDS` 用户 ID 白名单控制权限，默认关闭，不继承内容审核权限。
- `/api/finance/orders` 与 `/api/finance/orders/[orderNo]/refund` 提供仅财务管理员可见的整单退款操作。
- 支付域的 `reconciliation-service.ts` 在同一数据库事务中检查全量留存订单与充值流水。已付款缺流水、金额/用户/类型错误、未付款却已有流水及负余额都会列出，异常最多返回 100 条并明确标记截断。
- 近 1–90 天人民币已付款、完成退款及退款后金额分别汇总。AI 域的 `cost-report.ts` 按币种分别汇总成本、已知/未知成本次数、模拟调用及失败/取消次数。不把未知成本当作零、不混合币种、不把金额称作毛利润。
- 当前没有历史期初余额凭证，所以不把余额与流水合计差额自动判断为错账；报告也不会自动修正数据。
- EZFP V2 退款适配器使用 `/api/pay/refund` 和 `/api/pay/query`。每单仅允许一笔全额退款，签名响应确认成功后标记完成；明确拒绝时以新的返还流水释放金币；超时或验签失败时保留冻结金额，支持查单和同退款单号重试。退款开关 `EZFP_REFUNDS_ENABLED` 默认关闭。没有实现部分退款。
- 新迁移 `20261013000000_payment_refunds` 新增退款记录和金币流水退款扣留/返还引用，不删除或重写原充值流水。路由负责权限与 HTTP 映射，规则保留在支付/AI 服务域，页面只展示。
