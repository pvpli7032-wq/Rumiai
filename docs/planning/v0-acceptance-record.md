# V0（场景卡体验版）验收记录

> 状态：本地验收记录；不表示已上线生产。生产发布需由产品负责人另行安排。记录仅覆盖当前 V0 实现及现有测试证据。

## 交付范围

本轮交付为纯前端场景体验：

- 发现页精选场景区：展示绑定真实角色的精选场景入口。
- 角色详情弹层：场景头部及「进入场景」入口；普通角色维持原有详情与「开始聊天」。
- 公开角色页：仅为有可用场景配置的角色展示场景入口。
- 场景态聊天页：场景开场、三条建议动作、结束确认、本地回顾视图；建议点选仅填入草稿，用户仍需明确发送。

明确未做：章节状态不持久化；不判定章节完成；不影响或解锁下一章；不新增数据库表；不新增 API；不接入埋点。结束/回顾是本地体验态，不代表已保存章节结果。

## 不可用状态与降级

resolveScene 对应四种 unavailable 原因。前端依赖“只有 available 才渲染场景入口/场景态”，不可用时回退普通角色详情或原有聊天，不伪造场景内容：

| 原因 | 触发条件 | UI 表现 / 降级 |
|---|---|---|
| missing-config | 角色没有对应静态场景配置 | 普通角色详情仅保留「开始聊天」；公开角色页无场景入口；即使 URL 带 scene=1 也回到普通聊天。 |
| disabled | 配置显式关闭（enabled=false） | 不作为可体验场景发布；按普通详情/聊天降级，不显示场景头部、建议或结束入口。 |
| incomplete-copy | 必需字段为空，或建议数不是三条/建议 ID 或文本为空，或兼容性审核字段缺失 | 配置不发布、不出现不完整场景；沿用普通详情/聊天，避免补写或猜测文案。 |
| incompatible-character | 配置绑定的 characterId 与当前角色 ID 不同 | 不把该配置套用到错误角色；普通详情/聊天，无场景入口。 |

测试现状可直接证明 missing-config（含未知角色）、disabled、incomplete-copy、incompatible-character 在 resolver 层被区分；浏览器脚本具体覆盖无配置角色及缺少 scene 参数回退。其他各类场景 UI 降级仍应在新增负向 fixture/浏览器测试中逐项验证，不把 resolver 单测误报为所有 UI 分支均已覆盖。

## 测试覆盖与本地证据

本地实际执行结果（2026-10-20，本机隔离库，不连生产）：

```
$ node --import tsx --test tests/stories-v0.test.mjs
# tests 5 / # pass 5 / # fail 0

$ node scripts/run-browser-matrix.mjs scripts/verify-v0-story-browser.mjs
✔ scripts/verify-v0-story-browser.mjs PASS=11 SKIP=0 FAIL=0
```

- `tests/stories-v0.test.mjs`：5 个用例。场景/角色 ID 唯一、发布完整性、每场景恰好三条唯一非空建议、已发布数量；场景文案不含「已完成/已保存/下一章/记住你/永久记忆/会记得」；`resolveScene` 对 available、missing-config、incompatible-character、disabled、incomplete-copy 五类判定；未知角色缺配置时不臆造场景；回顾片段只取真实消息、跳过空内容、按时间取最近最多三条、超长截断，并覆盖空列表与上限 0/超限边界。
- `scripts/verify-v0-story-browser.mjs`：11 个 PASS 断言。发现页精选场景三个真实角色入口且链接带 `scene=1`；墨白详情弹层显示场景三要素与「进入场景」；无配置角色（林澈）保持原详情与「开始聊天」且不出现场景元素；场景态展示开场与三条建议、点选只填草稿不发送；结束确认文案为「只结束本次体验，不会判定章节完成。」；回顾视图为空态且不含完成/保存/下一章字样；回到聊天恢复输入区且 URL 不变；缺少 `scene=1` 回退普通聊天；未绑定角色带 `scene=1` 也不进入场景态；公开角色页只为绑定角色渲染入口且入口可打开；全程无前端运行错误。

证据产物（`V0_TEST_OUT`，默认 `Desktop/v0-story`）：`discover-scenes.png`、`dialog-scene.png`、`chat-scene.png`、`chapter-close.png`、`result.json`。

除上述浏览器脚本外，本轮还通过：`npx tsc --noEmit`（0 错误）、`node scripts/check-definition-of-done.mjs`（全部通过）、`npm run build`（生产构建成功）。

注意：`disabled` / `incomplete-copy` / `incompatible-character` 三种降级目前只有 resolver 层单测覆盖，没有对应浏览器负向 fixture；不要把这三种 UI 分支说成已被浏览器验证。

## 遗留风险与下一步

| 遗留项 | 为什么现在不做 | 谁在什么条件下做 |
|---|---|---|
| 正式内容审核 | 三个场景文案目前是内部审稿稿，虽有静态配置和内部兼容性字段，并未走正式内容审核流程；不能据此视为已批准生产内容。 | 内容负责人组织正式审核，逐场景确认身份/冲突/目标、建议动作、隐私边界和公开问题；审核完成且产品负责人批准后更新版本配置并重新验收，方可安排生产发布。 |
| 埋点缺失 | 本轮明确不接埋点；场景到达率、首条消息率、主动结束率、继续点击率均尚无事件/口径数据，V0 无法据此做数据验收或证明漏斗效果。 | 产品分析/数据负责人会同客户端与隐私合规负责人，在指标定义、分母/去重、字段白名单、留存期限及隐私评审通过后另立任务接入；发布前完成事件验证后再做实验评估。 |
| 本地化 | 当前场景文案仅中文，V0 先验证中文场景流程；非中文语言用户可能看到中文内容，体验不一致。 | 本地化负责人在目标语言与首发地区确定、文案审核/翻译资源到位后建立场景文案资源及语言回退规范；实现后逐语言验收，不得将未翻译状态误判为已支持。 |
| 章节持久化 | V0 是体验验证层，不新增表/API，不保存章节状态、不判定完成，也不改变下一章；当前回顾只基于既有消息的本地视图。 | 产品负责人在 V1 范围、章节/状态模型、完成语义、权限与迁移方案明确并批准后，安排后端/数据模型与前端实现；新增持久化/API 后制定独立迁移、权限和恢复测试。 |
