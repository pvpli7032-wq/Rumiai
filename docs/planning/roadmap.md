# 角色关系连续剧实施路线图

> 执行草案：M0 冻结后成为基线。依据规划书第 26、27、29 章及已核实运行约束，不承诺日历日期。团队是 AI 工作流，人日仅作相对体量参考。采用补丁 C 重拆口径：M3 9–12、M4 10–14、M5 8–10；总量 30–45 与重拆 44–58 的差异在 M0 校准并保留 20% 缓冲。

## 固定约束与编号
- 线上单机 Next + SQLite + PM2；每次发布按 30–60 分钟窗口，隔离库构建、3100 预启动、备份、切换、冒烟、观察、回退决策。
- Windows 本地 Prisma 使用 `npm run db:local`；浏览器验收读 `.next-build`。生产迁移命令以 M0 核实的 runbook 为准。
- 发布顺序：已完成后台重构 → V0 → V1 数据与记忆。M0 未确认契约、实际 schema/数据库映射前，不设计故事表或迁移。
- 唯一阶段编号 M0–M5；工作流 W01–W09；验收场景 A01–A13。

## 工作流拆分
按写作用域并发，不按人头拆分。负责角色是 AI 团队内的产品、前端、后端/数据、QA/发布、内容评测角色；最终集成与 diff 由 Lead 复核。

|---|---|---|---|---|
| W01 基线冻结 / 产品+后端接口 | 仅 `docs/planning/`；代码只读 | 后台重构发布状态可查 | 普通发送/重生成行为对照、接口/鉴权契约、边界图、基线与风险清单 | 两调用方逐项核对调用顺序、权限、结算、持久化、错误重试；确认真实 SQLite 文件/schema。未签核不进故事表设计 |

### 并行与串行
- `src/lib/conversations/**` 的任何实现/重构/合并必须串行，一次一个写入者，契约与回归通过后交接；普通发送、重生成、chat-application-service 接入不得并发改动。
- `prisma/schema.prisma` 和迁移序列串行编号、顺序验证。W05 冻结前 W06/W07 不得改字段。
- docs、W02 原型与只读盘点、独立 i18n 字典（先锁键名/所有权）、不改业务源的测试脚本可并行；W08 可先准备框架，真实评测等闭环。
- 同一页面/组件/迁移文件不多头修改。脚本需改业务源时移交源文件负责人。

## 发布批次
所有批次按 30–60 分钟窗口；记录 SHA、产物、备份位置/校验、执行人、时间、冒烟和回退决定。以下 npm 脚本是本机验收入口，不等于生产 shell runbook。

| 批次 | 内容 | 迁移 | 回滚位 | 验收命令与线上门 |
|---|---|---|---|---|
| R0 后台重构（当前先发） | 已完成后台重构，不混 V0/V1 | 按实际清单核实，不假设有/无 | 预发 SQLite 备份、前版 PM2 构建；不可逆迁移未有恢复策略则停发 | `npm run typecheck`、`npm run test:production:guards`、`npm run release:check`、受影响后台测试/`npm run test:admin:browser`；隔离构建→3100→备份→切换→后台冒烟 |
| R1 V0 | M1 签核页面、现有接口、分享历史、保留旧聊天 | 否 | 回前版应用，不回滚数据库；保留 R0 稳定构建/备份 | `npm run typecheck`、`npm run test:m2:browser`、`npm run test:m2:chat`、`npm run test:m2:context`、`npm run test:browser`、`npm run test:browser:matrix`（读 `.next-build`）；线上隔离构建、3100、备份、V0/旧聊天/后台冒烟 |
| R2 M3 扩展迁移 | 模板版本/StoryRun/Turn 兼容结构；记忆自动应用关闭 | 是，增量兼容 | 关新建/切旧读写、回前版；迁移前备份；不可逆 schema 不假设可降级 | `npm run db:local`、`npm run test:database:upgrade`、新增仓储测试、`npm run typecheck`、`npm run test:browser`；副本迁移/数据核对/恢复通过，线上备份、3100、旧聊天与新对象冒烟 |
| R3 M4 闭环 | 事件、章节、纠错失效、worker 恢复、评测 | 如有字段/索引则增量迁移，提交前明确 | 关记忆/章节写入，M3 数据只读，回前版；需要恢复时核对已提交对话 | 必要时 `npm run db:local`、`npm run test:database:upgrade`、`npm run typecheck`、A05–A08、获授权 `npm run test:real-ai`、`npm run test:browser`；3100 验证提交/失败/恢复/旧聊天 |
| R4 M5 试点 | 生命周期、导出/删除/恢复、负载与灰度 | 生命周期字段变更才迁移 | 关闭试点/写入、回前版、保留兼容数据；恢复演练不得覆盖未备份数据 | `npm run test:m5:backup`、`npm run test:m5:export`、`npm run test:m5:closure`、`npm run test:m5:recovery-runtime`、获授权 `npm run test:real-ai`、`npm run test:browser`；回退演练和告警门通过再扩量 |

### 发布固定操作门
1. 冻结 SHA、迁移清单、开关默认值、负责人和窗口；隔离环境构建。
2. 3100 预启动，不接线上写库；健康检查及目标版本冒烟。
3. 涉迁移先暂停相关 worker/写入，记录数据库版本，备份并验证可读/可恢复；只运行签核迁移。
4. PM2 切换后执行本批清单；浏览器验收读 `.next-build`。观察 5xx、写入错误/延迟、worker 租约、SQLite 锁等待、费用和旧聊天回归。
5. 达回退条件先关功能/写入、停 worker，再兼容切回旧应用；只有数据安全和备份一致性确认后才恢复备份。未知模型调用不得盲目重试。

## 关键路径与阻塞
关键路径：R0 后台重构发布 → W01/M0 契约与真实数据库映射 → W02/M1 原型 → W03/W04 V0 验收及 R1 → W05/M3 迁移与数据契约 → W06 单回合可靠性 → W08 M4 评测返工 → W07 生命周期/W08 性能 → W09/M5 灰度回退。M3 等契约冻结；M4 依赖 M3；M5 依赖恢复与因果验证；正式剧情评测等真实闭环。
当前阻塞：后台重构线上发布及观察结论；发送/重生成行为差异；SQLite 文件/schema 映射；迁移失败恢复责任人与 runbook；V0 用户理解门；V1 保留/删除/导出与 worker 运维策略。未清不得用假设替代批准。

## 变更控制
仅在 M0 发现实际接口/数据与假设不符、验收证明方案不可行、安全/隐私/数据丢失风险或生产约束变化、灰度未达门槛、容量/依赖有可验证变化时改规划。实现偏好、未经验证想法或单次模型波动不直接扩范围。
工作流负责人提交理由、影响阶段/工作流/路径、依赖/并行性、迁移回退影响、测试证据、风险成本和替代方案；Lead（项目总负责人）拍板范围、顺序和基线。涉及线上数据/迁移/发布窗口/隐私的操作，还须线上发布或数据责任人确认。更新本文版本和决策记录；未批准只登记候选，不进入执行。不得绕过备份、兼容、回退和验收门。

## 下一批可立即开工的 3 个工作流
1. **W01 基线盘点与冻结**：只读核查后台重构发布状态、发送/重生成行为、接口鉴权/返回、SQLite 文件与表映射；输出契约、边界图和迁移问题清单，不改业务代码。
2. **W02 交互原型**：与 W01 并行，完成五类核心页面、异常态、3 个开场及用户能否独立开始/继续和是否误解“记忆”的测试。
3. **W08 测试脚本/评测框架准备**：独立目录准备脚本骨架与 A01–A13 追溯矩阵；先做 M0/M1 可运行的回归，不把未实现 V1 功能记为通过，避免碰共享业务源。
