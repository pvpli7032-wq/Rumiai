# M1 / V0 交互与视觉规格

> 范围：V0 前端体验版的场景入口、聊天内建议动作与用户主动结束后的章节结束页。本文不承诺 V1 的长期记忆、自动判章或跨会话剧情状态。

## 1. 依据与设计边界

- 规划基线：《角色关系连续剧产品与实施规划书 V1.0》第 07–10 章。V0 只显示真实会话片段与用户主动记录；结束页不判定完成、不保存剧情结果、不改变下一章。
- 视觉采用“故事阅读室”：温暖中性色的内容气质、清晰正文层级、克制角色色与场景插画。复用 src/app/globals.css 的语义色（background、foreground、card、muted、border、primary、brand 等）及深色模式；角色色仅作头像/小面积识别，不表达成功、错误、警告。不要新增调色板或硬编码状态色。正文建议 16–18 CSS px、行高约 1.6–1.8，作为原型起点，需实机校准。
- Tailwind 断点仅确认有 desktop: 1024px；按此分界桌面/手机，不假设另有命名断点。移动布局同时遵循 --app-height、安全区、聊天视图和键盘隐藏导航规则。
- 现有 UI 是展示型原语，业务组件持有数据与事件。本文提及的 UI 名称与可用 props 以实际导出为准；所有布局类名建议只用标准 Tailwind 工具类和语义 token。
- V0 不因打开页面自动请求模型；场景建议动作不会代发消息。继续恢复原会话；不可宣称角色“记得”未在真实记录中出现的事。

## 2. 场景入口：StoryCard / SceneHeader

### StoryCard（发现列表中的场景预览）

- 内容顺序：场景标题与类型 → 一句事件钩子 → 角色头像/名称 → 适合谁/预计时长（仅内容团队提供时）→ “查看场景”入口。卡片封面使用场景插画，优先裁切为固定比例并延迟加载；图片失败时显示语义中性的背景与标题，不以角色立绘代替文本。
- 桌面：在内容网格中等宽排列，图像位于上半区、文字下半区；标题和摘要不覆盖插画，整卡不做嵌套卡。操作为明确的“查看场景”按钮/链接。
- 手机：单列整宽或既有网格自然单列；插画限制高度，标题/摘要可换行；首屏先展示一个主要场景入口。触控目标至少 44×44 CSS px，卡片正文与操作保持足够间隔。

### SceneHeader（场景详情顶部）

| 信息层级 | 用户需要读到 | 呈现要求 |
|---|---|---|
| 我是谁 | 本场景中用户的身份/位置 | 单独的“你的身份”标签与一至两句说明；缺字段不猜，显示“身份尚未说明”。 |
| 发生什么 | 当次事件、冲突与角色 | 标题、简短冲突摘要、角色 Avatar 与名称；只展示公开开场信息，不泄露隐藏真相。 |
| 这次要做什么 | 本次目标/开始方式 | 一句可行动的目标；主操作“开始体验”，已有会话改为“继续上次对话”，并显示真实最后位置/更新时间。 |

- 桌面：内容主栏最大宽度约 960px；插画与身份/事件文本可并排，CTA 置于信息之后且视觉单一。避免把全部资料塞入首屏侧栏。
- 手机：纵向顺序为标题、角色、身份、冲突、目标、动作；插画不超过首屏约三分之一高度，CTA 全宽或自然宽度并固定在内容流中，不盖住文本/键盘。
- “重新开始”不得与“继续”混成一个操作：若 V0 现有后端无法明确创建新会话，则不显示重新开始；不把新场景接入角色旧 scenario 不一致的会话。
- 三个建议动作以三枚有文字说明的按钮呈现，按可预期行动排序；桌面可横排，窄屏纵排或换行。每条是可编辑草稿的快捷入口，不自动发送。首发场景的静态配置必须恰好三条互不相同的动作；配置不完整时整条场景不进入 V0 入口，既不编造凑数，也不“少显示几条”（口径见 m1-v0-scope.md 第 6 节）。

### 场景入口四态

| 状态 | 用户看到什么 | 可操作项 |
|---|---|---|
| 空 | EmptyState：“暂时没有可体验的场景”，说明可返回发现/角色页；不生成假推荐。 | 返回/浏览其他内容。 |
| 加载 | StoryCard 骨架占位，标题区域有稳定尺寸；辅助技术不朗读装饰骨架。 | 无；旧内容若仍有效可保留且标为正在刷新。 |
| 失败 | ErrorState 明确“场景暂时无法加载”，说明不影响已有会话。 | Button 重试、返回。 |
| 角色下架 | 说明角色/场景暂不可开始；若拥有历史会话，提供查看原会话/记录入口（仅审核策略允许时）。 | 不允许新开；不将不可用伪装为空或可继续。 |

## 3. 聊天内 ActionSuggestions 与 ChapterClose

### ActionSuggestions

- 只在场景开场/上下文合适时显示建议动作；首发场景应恰好 3 条，界面最多渲染 3 条作为防御；自由输入始终可用。按钮文案是一条用户可直接编辑的第一人称意图，避免选择标签看起来像不可更改的剧情分支。
- 点击：将完整文本放入当前 Composer 草稿并聚焦输入框；不触发网络请求、不自动发送、不改变故事状态。若草稿已有内容，采用追加到光标位置（以换行分隔）的规则，不覆盖用户文字；如当前编辑器不能可靠支持光标插入，点击后保留原稿并在输入框尾部追加，测试验收此规则。
- 已有草稿时建议动作仍可用；正在生成时不丢弃草稿。建议内容不作服务器事实，发送前用户可任意编辑或清空。
- 建议按钮用现有 Button 的 variant=outline 或 secondary，有可读文本与清晰焦点样式；不把角色主题色当状态色。

### ChapterClose（V0 用户主动结束页）

- 触发只来自聊天界面的明确“暂时结束本章/结束这次体验”操作和确认，不因消息数、超时、模型判断或离开页面自动出现。确认文案说明“这只结束本次体验，不会自动判定章节完成”。
- 真实片段：从当前原会话展示 1–3 条经长度截断的真实消息摘录，标注说话者/时间；无片段时如实显示“还没有可回看的片段”。不显示模型生成摘要为事实。
- 未完成问题：仅展示场景正文已提供的公开问题/目标，标签用“还可以继续探索”；不声称为系统记忆或承诺。没有可靠字段时显示明确空态“还可以继续探索的问题暂未整理”，不隐藏该区，也不臆造问题（口径见 m1-v0-scope.md 第 6 节）。
- 入口：主按钮“继续这段对话”回到同一会话并定位最近消息；次按钮“回到原会话”回到聊天上下文（若二者语义相同则只显示一个，避免重复入口）。结束页不提供未实现的“下一章/保存结果”。
- 桌面：内容居中、最大宽度约 720px，回顾片段在主区，两个入口同一操作区；装饰插画次要。
- 手机：纵向单列，摘要、片段、未完成问题、继续入口依次出现；主要继续操作位于内容末尾且键盘关闭时可见，不强制一屏塞满；关闭键盘/结束确认后滚动定位到标题。

### 移动端键盘与滚动

- 输入控件遵守 globals.css 手机字号至少 16px 规则，避免 iOS 自动放大。使用动态视口与安全区，不用固定屏幕高度假设；键盘打开时隐藏 mobile-primary-nav、减少 app-content 底部占位（现有 CSS 已有 data-keyboard 约定）。
- 键盘打开/关闭不清空草稿；Composer 保持可见，输入框上方最后一条消息不被遮挡。发送后仅在用户本来位于底部时自动贴底；用户上滑读历史期间保持当前位置，并提供明确“回到最新”操作。
- 新消息/流式回复追加时不每 token 滚动；按批次更新并在接近底部时轻量跟随。键盘弹出、切换会话、打开结束确认均需真机检查中文输入法组合输入、长文本粘贴、横竖屏与安全区。

## 4. 新增界面状态矩阵

矩阵涵盖两个新增界面：SceneEntry（场景卡列表/详情入口）与 ChapterClose（用户主动结束页）。每格均明确用户可见反馈；“下架”优先于普通数据空态。窄屏列表示正常内容在窄屏下的实际呈现，而不是另一个业务状态。

| 新增界面 | 正常 | 空 | 加载 | 失败 | 权限不足 | 下架 | 窄屏 |
|---|---|---|---|---|---|---|---|
| SceneEntry / StoryCard、SceneHeader | 有效场景显示插画、角色、身份、冲突、目标；最多 3 个真实建议动作；CTA 为开始或继续。 | EmptyState 说明无可用场景，给返回发现入口，不展示虚构继续故事。 | 骨架占位保持布局尺寸；不把骨架读给屏幕阅读器。 | ErrorState + 重试；已有会话链接仍可用。 | 明确说明需登录/当前账号无权开始；提供登录或返回入口，不泄漏私有场景信息，也不呈现为空。 | 明确“该角色/场景暂不可开始”；允许的历史只读入口保留，开始按钮不可用/不渲染。 | 1024px 以下纵向布局；插画限高，正文优先，动作可换行，CTA 不遮挡。 |
| ChapterClose | 展示 1–3 条真实原文、可用的公开未完成问题，以及回到同一原会话的入口；提示 V0 不自动结章。 | 如无可回看消息或公开问题，分别显示真实空文案；“继续对话”仍回原会话。 | 若真实片段仍在读取，显示段落骨架和“正在读取本次对话片段”，不先渲染空结果。 | 加载片段失败时说明无法读取，提供重试和返回原会话；不伪造摘要。 | 会话所有权校验失败时说明无法访问此对话，清除/不渲染缓存正文并提供回到安全入口。 | 场景下架时保留允许用户查看的本会话片段；明确不能新开或继续场景，遵从审核策略隐藏不允许展示的内容。 | 单列可滚动，标题和主入口清楚；不横向溢出，不要求内容塞入一屏。 |

状态处理通用规则：有可缓存的真实会话内容时，刷新失败可保留并标明旧数据；401/403 与 404/审核下架不能共享空态；重试不自动触发模型请求；错误提示不覆盖可访问的返回路径。聊天中的流式、取消、余额不足和断流继续遵守既有聊天行为，不伪造 ChapterClose 成功状态。

## 5. 无障碍与输入/焦点

- 键盘路径：Tab 顺序按阅读顺序经过返回、开始/继续、建议动作、消息列表中的必要控件、输入框、发送、结束体验；Shift+Tab 反向可预期。Enter 仅执行当前聚焦按钮的明确动作；建议动作键盘激活只填草稿。可见焦点使用现有 focus-visible:ring-ring 语义，不移除轮廓。
- Dialog/Sheet：现有原语声明 modal dialog 语义并支持关闭键/遮罩关闭，但源码未提供完整 focus trap、打开时初始焦点、关闭后恢复焦点的保证。调用端不得假设这些能力；需在业务实现中管理初始焦点与恢复到触发元素，并验证 Tab 不逃出弹层。若原语实现不足，应另开组件层工作，不在本规格中假定 API。
- 结束确认关闭后焦点回到触发按钮；成功进入 ChapterClose 后将焦点移至页面标题并使标题可程序聚焦。加载完成/失败不抢焦点；错误区域用可见文案及 role=alert 的 ErrorState，toast 只用于非关键保存/恢复提示。
- 屏幕阅读器：消息列表使用有名称的区域；新消息流不要将每个 token 放进实时播报区。模型生成期间仅播报一次“角色正在回复”，提交后播报完整消息或简短“新回复已完成”，允许用户按需移至新消息。错误与保存确认独立播报；装饰图 alt 为空，信息图像提供准确替代文本。
- 输入关联：Composer 有始终可见/可读标签；建议动作组有标题；发送中/禁用状态有文本信息，不能只靠颜色或 spinner。对比度检查正常/深色模式、正文、角色色与焦点态。
- 动效：遵从系统 prefers-reduced-motion（globals.css 已有全局规则）；不自动播放背景视频、循环立绘或粒子效果。减少动态效果时取消平滑滚动和非必要过渡；加载骨架可静态呈现。

## 6. 新增组件清单与复用方案

新增业务组件只建议列出 V0 直接需要者；目录归属由主要领域职责决定。

| 建议文件 | 目录 | 职责 |
|---|---|---|
| story-card.tsx | src/components/stories/ | 发现列表中的 StoryCard；显示场景插画、标题、钩子、角色及进入详情操作；处理缺图回退呈现。 |
| scene-header.tsx | src/components/stories/ | 详情头部 SceneHeader；按“我是谁/发生什么/这次要做什么”组织真实场景数据，区分开始与继续。 |
| scene-entry-state.tsx | src/components/stories/ | 场景加载/空/失败/权限不足/下架状态文案与退路；复用通用 EmptyState/ErrorState，不复制底层原语。 |
| chapter-close.tsx | src/components/stories/ | 用户主动结束后的结束页视图；只呈现来源可核对的原会话片段与公开问题、回原会话入口，不写入结章状态。 |
| action-suggestions.tsx | src/components/chat/ | 最多 3 个建议动作；接收选择回调，把文案交给现有 Composer 草稿处理，不直接请求发送接口。 |

放置理由：StoryCard、SceneHeader、状态与结束页依赖场景/章节呈现概念，归 stories/；ActionSuggestions 与输入草稿、聊天发送工作流紧耦合，归 chat/。此为建议命名，不代表当前已有这些文件或导出。

### 复用现有 UI 原语（真实 API）

- Button：variant 为 primary、secondary、outline、ghost、danger、success、link；size 为 sm、md、lg、icon；另有 loading、fullWidth、leadingIcon、trailingIcon。它只负责呈现，行为由业务组件提供。
- Card、CardHeader、CardTitle、CardDescription、CardContent、CardFooter：仅作为基础卡布局，不把页面段落做成套娃卡。
- Avatar：src、alt、name、size（xs–xl）、shape（circle/rounded）；缺图有首字母回退。
- Badge：variant 为 neutral/brand/success/warning/danger/outline，size 为 sm/md；只用于短标签。
- EmptyState：icon、title、description、action、className；调用端提供文案与 Button/Link。
- ErrorState：title、description、action、className；默认 role=alert，可放重试 Button。
- Skeleton：shape 为 text/circle/rect、className；SkeletonText 有 lines 与 className。骨架默认 pulse，减少动态效果需按现有全局 CSS 检查。
- Textarea：原生 textarea props、invalid；默认 4 行。Input 有 size（sm/md/lg）与 invalid；手机全局 CSS 强制输入字体 16px。Select 是原生 select，传 option children，有 size、invalid。Composer 若已有组件则沿用，不为建议动作另造输入 API。
- Dialog：open、onClose、title、description、children、footer、size（sm/md/lg/xl/full）、closeOnOverlayClick、hideCloseButton、className。手机底部停靠，sm 以上居中。用于结束确认时仍须验证焦点 trap/恢复，API 不保证这些行为。
- Sheet：open、onClose、title、description、children、footer、side（right/left/bottom/top）、closeOnOverlayClick、hideCloseButton、className；可作移动资料抽屉。
- ToastProvider / useToast：用于非关键的短暂状态通知；权限失败、模型失败等必须保留页面内文案，不只 toast。
- Tooltip：content、side、delay、children、className；仅为可视控件补充提示，不承载必需信息。
- Tabs、TabsList、TabsTrigger、TabsContent：确有互斥分区时使用；当前场景头与结束页没有必要用 tab 隐藏关键内容。
- DataTable、Pagination：不适用于单场景阅读/章节结束主流程；勿为视觉统一强行套用。

原语来自 src/components/ui/index.ts 的导出清单。不得假定 Modal、SkeletonCard、Toast 单函数、focus-trap prop、按钮 href prop 或新的颜色 token 等未核实 API。业务组件负责语义标题、数据来源、响应式布局、焦点生命周期与业务操作；原语仅提供当前明确能力。
