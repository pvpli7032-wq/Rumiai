# M1 / V0 范围冻结与验收口径

> 状态：V0 交付基线。依据《角色关系连续剧产品与实施规划书 V1.0》第 05、08、09、10、13 章及补丁 A；字段来源依据指定页面、目录服务与 Prisma 模型核对。V0 是前端体验验证，不代表长期记忆、剧情因果或商业化完成。

## 1. 范围与字段来源

### 1.1 场景卡 / 场景详情

**规格**：开始聊天前呈现角色、用户代入身份、当次冲突、当次可执行目标及开始方式；首屏让新用户 3 秒内读出“我是谁、我要做什么”。开始动作进入对应角色会话，不得自动发送消息。

**真实来源**：Character 有 name、tagline、personality、background、greeting、roleTemplate、scenario、tags、avatarUrl。catalog-service 的详情读取返回完整角色；公开角色读取当前只选择 id/name/tagline/greeting/personality/avatarUrl/chatCount/tags。详情页实际展示角色名、tagline、标签、聊天数、问候语；卡片展示角色名、tagline 或 personality、标签。它们是真实角色数据，但不是结构化场景字段的可靠替代。

**内容/空状态**：首发角色身份、冲突、目标须有经审核的场景文案。若从现有 roleTemplate / scenario / background 整理，必须由内容负责人逐条确认，不得运行时臆造。当前模型没有独立的身份/冲突/目标字段，结构化字段标记为“需新增（V1）”。V0 使用经审核的受控静态配置或现有内容字段，实施前确认承载方式，不新增业务表。缺少任一必需文案时不展示不完整场景卡、不猜测补齐；该角色不进入 V0 场景入口，旧自由聊天仍可用。无图沿用现有占位；下架/不可见时明确提示不可开始。

**不做什么**：不做多分支独立故事模板、动态场景生成、隐藏真相揭示、自动开始/自动发送、完成条件、客户端覆写角色全局 scenario、跨会话记忆或新业务表。

### 1.2 三条建议动作与自由输入

**规格**：聊天开场显示恰好三条与场景相符的建议动作。点选只把文本放入输入框，用户可编辑、清空、改选；须由用户明确点击发送后才成为消息。自由输入始终可见可用。新用户从可交互开场到首条成功消息的目标为 30 秒内。

**真实来源**：Message 保存 USER 消息正文、创建时间和会话关联；聊天页有输入/发送流程及 greeting 空会话开场。Character 有 greeting/personality/scenario 等文本，但没有建议动作列表或场景关联字段；建议动作数据标记“需新增（V1）”。V0 可使用随版本发布、经内容审核的静态配置；缺配置时不渲染建议，不能以通用伪建议替代，自由输入仍可用。

**空/异常**：无建议时显示正常输入；greeting 为空沿用现有开场兜底。发送失败保留草稿并展示错误；发送中避免重复提交；失败不计为首条消息成功。

**不做什么**：不自动发送建议、不限制改写、不隐藏自由输入、不以模型示例回复冒充真实消息、不因点选建议单独触发模型或计费请求。

### 1.3 用户主动结束与章节结束页

**规格**：用户主动选择结束/暂时离开后展示结束页，包含本章真实对话片段、未完成问题及继续入口。片段必须引用当前会话已保存消息。未完成问题只能采用用户可见的真实对话原文或经审核的 V0 内容，不得作为模型判定事实。提供回到原会话；**V0 不提供「进入下一章」入口**——V0 未发布任何后续章节，展示该入口会把「结束」误解为解锁或状态迁移，因此该入口整体推迟到 V1（见下方口径冻结）。验收须能从结束页回到原会话。

**真实来源**：Conversation 有 id/userId/characterId/title/createdAt/updatedAt；Message 有 id/conversationId/role/content/createdAt。可用于授权读取真实历史片段与原会话回跳。Conversation 没有章节标识、结束状态/时间、结果或未完成问题字段；Message 无精选标记。章节、持久结束状态、结构化未完成问题、完成结果均标记“需新增（V1）”。V0 结束由用户操作临时触发，不保存结束结果。无未完成问题依据时显示明确空态“本章没有整理出的未完成问题”，不生成虚构问题。

**空/异常**：无消息时显示暂无可回顾片段并提供返回；无问题显示明确空态；加载失败提供重试/返回；无下一章时不显示失效入口；无权访问不泄露消息。

**不做什么**：不判定完成、不保存结果、不改变/解锁下一章、不写长期记忆、不自动结束、不新增章节/结果表。不声称“共同经历已记住”或“承诺已完成”。

## 2. 浏览器验收清单

- 完整场景详情首屏同时呈现身份、冲突、目标；首次可见起 3 秒内可读，无需展开隐藏区。
- 缺身份/冲突/目标时不出现编造文案；角色不进入 V0 场景入口，但旧自由聊天可用。
- 开始前无用户消息自动发出；明确开始后进入对应角色聊天。
- 首发场景的开场恰有三条建议；点选后文字出现在输入框，可修改/清空；点选本身不发送消息。
- 无建议配置时仍可直接自由输入发送，输入框不隐藏或禁用。
- 首条消息计时从开场可交互开始，到首条用户消息成功保存；目标不超过 30 秒。点选、输入未发送、发送失败均不算成功。
- 用户主动结束后出现结束页；有真实已保存消息片段或无消息空态。
- 未完成问题有依据内容或明确空态；不展示编造为事实的承诺/结果。
- 点击回原会话后打开同一角色、同一会话，并能看到原有真实消息。
- 结束页不出现任何「下一章/继续下一章」入口（V0 未发布后续章节）。
- 刷新/重新进入旧会话链接仍打开原会话；无权访问时不展示他人消息。
- 结束流程不产生完成判定、持久章节结果或自动解锁/改写下一章。
- 旧自由聊天可用，旧角色链接有效；不出现新增付费墙或新增付费拦截。

## 3. 实验目标、指标与事件

### 3.1 指标定义

分开报告两个目标：A）场景化体验是否更容易开始；B）章节是否有收束感、用户是否愿意继续。按实验组、角色/场景版本、设备类型、新老用户分层；报分子、分母、样本量、观察窗口。排除内部/测试流量，固定去重规则；不得以总消息数上涨作为通过条件。

- **开场到达率**：成功进入可交互 V0 聊天开场的去重用户数 ÷ 成功展示合格场景详情的去重用户数。同一访问流程；加载失败/权限拒绝不进分母，另报失败率。
- **首条消息发出率**：开场到达用户中，开场后 30 秒内至少一条用户消息成功持久化的去重用户数 ÷ 开场到达去重用户数。计时从可交互开场至首条保存消息；点选、草稿、失败均不算。
- **主动结束率**：至少发过一条成功用户消息的去重会话中，观察窗口内主动触发结束的会话数 ÷ 同批已发消息会话数。窗口在实验前统一；系统关闭、跳出、超时不算主动结束。
- **结束页继续点击率**：已展示结束页的去重会话中，至少点击一次回原会话或有效下一章的会话数 ÷ 已展示结束页去重会话数。分别报两个目的；另报目标实际打开率，点击不等于继续成功。

### 3.2 事件与字段

只记录标识、时间、状态、耗时及必要实验分组/版本属性。禁止记录聊天正文、输入草稿、建议文字、提示词、片段正文、备注或正文哈希。分析用假名化用户标识并设留存期限。

| 事件 | 触发 | 字段（除通用字段） |
|---|---|---|
| scene_detail_view | 场景详情可交互展示 | scene_id、scene_version、experiment_arm、load_duration_ms |
| story_opening_reached | 聊天开场可交互 | scene_id、conversation_id、elapsed_from_detail_ms |
| suggestion_selected | 建议填入输入框 | conversation_id、suggestion_id（不含文字）、elapsed_from_opening_ms |
| first_message_sent | 首条用户消息确认保存 | conversation_id、message_id、is_first_user_message、elapsed_from_opening_ms |
| chapter_end_requested | 用户主动结束 | conversation_id、elapsed_from_first_message_ms |
| chapter_end_viewed | 结束页成功展示 | conversation_id、load_duration_ms、has_real_excerpt、open_question_count（只数量） |
| chapter_continue_clicked | 点击结束页入口 | conversation_id、destination（same_conversation / next_chapter）、elapsed_from_end_view_ms |
| chapter_continue_opened | 目标实际打开 | conversation_id、destination、open_duration_ms |

通用字段：event_id（去重）、occurred_at（UTC）、anonymous_user_id（假名化，可空）、session_id（分析会话标识）、status（success/failure/cancelled 等受控值）、duration_ms（适用时）。不得将 IP、邮箱、昵称等额外个人资料加入产品分析事件；安全日志与分析事件分开管理。

## 4. 与现有功能的边界

- **旧自由聊天保留**：现有角色聊天、输入、历史、编辑/重生成继续可用。V0 场景仅作引导，不强制所有对话进入章节流程。
- **旧链接不失效**：旧角色详情链接仍到原详情；旧聊天/会话链接仍打开原会话。历史自由聊天不自动迁移为故事。
- **不新增付费墙**：不增加新收费层、章节付费解锁或由建议/结束页触发的付费拦截；现有账号、额度、结算规则不变，沿用原错误和余额提示。
- **不新增业务表**：V0 仅用现有 Character、Conversation、Message 真实数据与不持久化的前端临时状态；不借用关系数值伪装章节状态。
- **结束语义**：用户主动离开当前体验的导航/展示行为，不等于章节完成；结束页点击不持久改变后续剧情。

## 5. V0 需要的最小改动清单

这是实现 V0 的最小方向清单；本任务只交付本文件，不授权修改其他文件或代码。不新增业务表。

1. 为首发角色审核完整身份、冲突、目标文案；用无业务表的受控静态配置或既有内容字段承载，并确保详情页能读取。缺字段时排除场景入口。
2. 为每个首发场景提供三条建议动作及稳定 suggestion_id；聊天页点选填入、可编辑/清空/改选，始终保留自由输入。
3. 增加主动结束入口和结束页；只读取当前授权会话真实片段；未完成问题使用审核内容/真实原文依据或空态；提供回原会话，只有存在有效下一章才显示该入口。
4. 覆盖加载、空、失败、无权限、窄屏状态；不改变现有聊天保存、额度、认证和旧链接语义。
5. 接入不含正文的最小分析事件及漏斗汇总，校验字段白名单、去重、30 秒窗口和分母口径；复用合规分析设施。若无适用设施，先确认基础设施方案，不把聊天内容写入日志。
6. 用浏览器端到端断言覆盖第 2 节，并对新用户 30 秒首条消息流程做可重复计时验证。

**V1 明确范围**：结构化身份/冲突/目标与多模板模型、章节/故事实例、持久化结束结果、自动完成判定、结构化未完成事项、跨会话连续性均需另行立项；不属于 V0 承诺。

## 6. 口径冻结（V0 唯一口径，覆盖本文件与 m1-v0-ux.md 的冲突处）

内容正式审核发现本文件与 `m1-v0-ux.md` 有三处口径互相矛盾。以下为冻结后的唯一口径，两份文档以本节为准：

1. **结束页后续入口**：V0 结束页只提供「继续这段对话」与「回到原会话」；不提供、也不显示任何下一章入口。理由：V0 未发布后续章节，该入口会让用户把「主动结束」理解为解锁或状态迁移。下一章入口随 V1 章节持久化一并立项。
2. **公开未完成问题的空态**：无可靠公开问题时显示明确空态（“还可以继续探索的问题暂未整理”），**不隐藏该区**。理由：隐藏会让用户以为页面缺失或加载失败。
3. **建议动作条数**：首发场景的静态配置必须恰好三条，且三条必须是互不相同的动作；配置不完整（不足三条、文案为空、ID 重复）时整条场景不进入 V0 入口，而不是“少显示几条”。界面上最多渲染三条，属实现侧的防御，不是允许配置少配。

以上三条同时是发布阻断条件；任一条被改回原冲突口径，V0 不得发布。
