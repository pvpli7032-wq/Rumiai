# M0 风险清单

依据规划书第28章TABLE 26（文本548–558行）扩展；负责人为角色建议，不表示已经分配个人。

| 风险 | 早期信号 | 应对 | 负责人角色 |
|---|---|---|---|
| 只是换皮 | 首日点击增加但无人继续原故事 | 重做场景冲突和因果反馈；V0开始/主动结束指标与V1七日续玩分开验证，暂停扩展 | 产品负责人 + 内容负责人 |
| 剧情假记忆 | 用户未答应却被说成答应；猜测写成事实 | 关联来源消息/明确选择；候选待确认；覆盖拒绝、猜谜、纠错、回退评测 | 故事工程负责人 + 内容审核 |
| 内容供应不足 | 首章完成后无第二章或无法继续 | 完成第二章并内测后再扩大获客；固定版本 | 内容负责人 |
| 后端范围膨胀 | 出现第二套账号、支付、余额或通用模型网关 | 复用现有账号、支付、AI、聊天模块；按模块边界评审并记录重大决策 | 技术负责人 |
| 成本失控 | 每条消息触发多个模型；上下文持续增长 | 结章/关键节点才抽取；设上下文预算；按回合记录实际费用 | AI/成本负责人 |
| 复制代码拖入依赖 | 组件要求整套状态服务端或无关依赖增加 | 提取最小交互组件；先核对现有UI/API；记录采用的第三方依赖 | 前端负责人 |
| 修改历史产生矛盾 | 删除消息后旧约定仍有效或新旧后果并存 | 按回合使后续事件/快照失效，提升revision，从有效检查点重建 | 故事工程负责人 |
| 隐私外泄 | 分享卡出现备注、私人身份或未选片段 | 发布前预览、字段白名单、公开快照与私密数据分离、复用帖子权限 | 隐私/安全负责人 + 社区负责人 |
| 国际化只翻 UI | 英文场景仍混有中文提示或素材 | 按语言版本验收完整故事流程，不用UI翻译代替内容本地化 | 内容负责人 + QA |
| 流断开结果不明 | 断流后无法确认是否保存，重试可能重复生成/计费 | 区分committed与done；先查持久回合/调用记录；未知结果不自动重发 | 后端负责人 + AI平台负责人 |
| 发送/重生成行为漂移 | 抽取后文案、Retry-After、取消或原回复保留语义改变 | 以m0-behavior-parity.md逐项做契约回归，明确保留差异 | 后端负责人 + QA |
| SQLite写竞争 | 并发锁等待、延迟或失败率上升 | 固定负载测量p50/p95、锁等待和错误；先查事务/热点，再基于证据评审迁库 | 平台/数据库负责人 |

原始前九项来自规划书第28章；其余是结合第14、19章聊天执行与幂等要求的工程扩展。性能和成本目标须测量后确认，不代表已有验证结果。
