# 财务与充值

管理入口为 /finance。查看需要 finance.read，套餐修改需要 finance.packages.write。退款申请需要 finance.refunds.request，另一位管理员批准/驳回需要 finance.refunds.approve；申请人不能自批。审批后查单和同单号重试需要 finance.refunds.execute。申请先冻结金币，驳回或渠道明确拒绝时返还；结果不明时继续冻结，等待渠道查单。运营身份和权限由管理模块提供，金额与状态流转由支付领域服务决定。

## 套餐与活动

默认三档为6元60金币、10元100金币、30元300金币。支持新增、编辑、上下架、排序和定时赠币；活动按服务端时刻生效，后台按设备时区输入。版本冲突返回409。旧订单保留价格与金币快照，下架不改变历史订单。初始化仅补缺，不覆盖人工配置。

## 订单、退款与对账

仅支持整单退款。提交后先冻结订单金币；渠道明确拒绝以新流水返还，超时或验签结果未知继续冻结，查单及重试沿用原退款单号。退款默认关闭，不得用浏览器返回结果发币或直接修改余额。

`/finance` 已有不可变的渠道账单导入批次：标准化 CSV 表头为 `trade_no,out_trade_no,money,fee,paid_at,status`，金额为元，时间带时区；导入时需指定完整核对时间范围。服务对比本地渠道交易号、商户订单号、人民币金额和支付状态，并找出账单孤单与本地已支付但账单缺失订单，计算账单手续费并保留差异；文件和时间范围相同则幂等，导入不会写订单状态或金币账本，原文件不入库。单次本地支付订单上限5000笔，超出需缩短范围。真实易支付商户后台导出格式尚未做映射，正式对账前需用实际导出字段验收。

当前项目使用 EZFP V2 RSA 接口。[公开V2文档](https://www.ezfp.cn/doc/pay_query.html)说明的是单笔订单查询；[旧版文档](https://www.ezfp.cn/doc_old.html)列有批量订单/结算查询，但属于旧协议，不能直接当成当前 V2 商户的账单接口。手续费与结算额也分属不同金额，[费率说明](https://www.ezfp.cn/doc/fees_settlement.html)指出实际成本需依据商户支付方式费率和结算规则核对。

报告在同一只读事务中检查充值和退款流水、负余额及异常，并按1/7/30/90天统计人民币付款、退款金额。未建立历史期初凭证，不据流水合计自动调整余额；异常列表有100条上限和截断标识。

## 成本与指标

AI成本按币种分别汇总；模拟、失败、取消和未知费用分别显示。未知费用不能视为零，估算不能替代供应商账单。预算提示与可选自动熔断归AI领域，后台展示不决定接纳结果。

新注册付费率为同期注册且同期付款用户数除以同期注册用户数，同一用户多笔付款只计一次。退款率为同期付款订单中成功整单退款订单数除以同期付款订单数。零分母返回null。每千次调用成本按非模拟调用次数计算，含失败和取消；有未知费用时不计算。未有完整人民币成本及渠道费用时毛利率为null。

## 验证与待完成

支付检查使用生成的本地密钥、模拟渠道和隔离数据库。历史订单/退款集成、价格快照、活动并发与浏览器验收已记录在待完成清单；真实商户沙箱、渠道账单、手续费仍待验收。聊天扣币等待运营提供成本和价格，方案见[收费方案](收费方案草案.md)。
