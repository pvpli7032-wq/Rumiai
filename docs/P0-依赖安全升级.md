# P0 依赖安全升级

日期：2026-10-13（Asia/Tokyo）。状态：原生产与构建工具链依赖告警均已消除，主项目全依赖审计为零；整体上线验收仍未完成。

## 权威证据

修复前为 Next.js 14.2.35，官方 npm 生产依赖审计返回 1 项 critical、3 项 high（Next.js、nanoid、PostCSS、source-map-js）；该记录为修复前快照，不是当前状态。

Next 官方 [Windows RCE 公告](https://github.com/vercel/next.js/security/advisories/GHSA-p293-qw3h-jr36) 指明影响 >=13.4 且 <15.5.24，或 >=16.0 且 <16.3.3 的 Windows 服务，修复版本为 15.5.24/16.3.3，没有已知 workaround。[AVIF 优化 RCE 公告](https://github.com/vercel/next.js/security/advisories/GHSA-2xp9-vwfh-vxw4) 也列出相同最低修复版本。

本项目使用 Windows 和 App Router，原版本落在影响范围；没有运行漏洞利用，也没有发现或声称已有入侵。已升级到安全补丁版本。

## 修复范围与方案

本轮另修复了生产认证配置缺口：长的公开示例 JWT 值原来能通过长度检查，现在拒绝示例/空白/短值，注册前检查以避免先写账号再签名失败。CI 改用动态生成并屏蔽的测试认证密钥。`test:auth-config` 证明拒绝配置时不新增用户。

选择 npm 当前 15 系列最新补丁 15.5.27，而非直接跃迁到 16。按[官方 15 升级说明](https://nextjs.org/docs/app/guides/upgrading/version-15)核对 React、依赖与异步请求参数，保留业务域与数据库。

- 依赖与锁：Next.js、匹配 React/React DOM 与类型，必要的 React peer 兼容库；修复 PostCSS、nanoid、source-map-js。
- 动态 HTTP 路由：context.params 的异步读取与签名；离线旧对象调用仍可由 await 处理。
- 公共页面/metadata/layout：params/searchParams 异步读取，客户端使用现有 useParams 或兼容方式。
- 检查缓存默认值、图片访问/缓存与 SSE 行为，调整构建/CI 命令和文档。
- 不搬迁无关业务目录，不重建账户/订单数据库，不用 reset/db push；保留历史迁移和真实数据。

修改前保存源码与依赖清单快照；更新后完成类型、构建、生产依赖复审、安全/权限/支付/计费相关回归、HTTP/SSE 及浏览器完整路径。保留本轮注销/图片验收作为行为基线，框架升级后需要在新版本再验证。

旧版本仅可作为排错快照，不能把回滚到已知漏洞版本作为公开部署方案。真实模型/支付/商户/真机/灰度依赖仍保持原门禁，升级不替代它们。
