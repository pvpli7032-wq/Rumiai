# 项目结构与模块归属

本文件说明本次确认的目标结构及维护规则。目录迁移、类型检查、构建通过、业务验收和线上发布是不同阶段，不互相替代。

## 目录结构

```text
apps/
  web/                 用户前台、页面、前台认证状态和界面功能
  admin/               独立后台、后台登录、管理界面和后台 Cookie 请求
  api/                 HTTP 路由、支付回调、请求校验与应用装配
  worker/              后台任务常驻进程入口
packages/
  backend/
    src/modules/       业务模块及其服务入口
    src/workflows/     跨模块流程，例如会员购买与退款
    src/infrastructure/ 数据库、日志、HTTP、认证等服务端基础能力
  contracts/src/       前后台与 API 共用的数据结构、枚举和校验规则
  ui/src/              共享基础组件、主题与样式
database/              Prisma 模型、迁移及初始化数据
content/               随版本发布的故事内容
ops/                   运行、发布检查、备份恢复及架构检查
tests/                 单元测试和隔离数据库集成测试
docs/                  架构说明与验收结果
```

## 依赖方向

前台和后台通过 HTTP 调用 API，不导入数据库、后端服务或另一个应用的实现。后端不得依赖任何应用目录。共享 UI 不持有业务数据或支付规则。contracts 不依赖后端、应用、数据库或 Node 专用能力。

API 负责身份、请求形状、响应与错误状态的转换；业务规则只维护在对应后端模块。会员与支付的跨域编排放在 workflows，不复制到页面和回调。模块之间使用明确的服务入口，不从另一模块复制内部实现。

新增功能时先确定业务归属：页面写入对应应用，规则写入业务模块，公开输入输出写入 contracts，涉及多个模块的提交过程写入 workflows。只有确实存在共享消费者的基础组件才放入 ui，不把业务组件随意塞入共享包。

## 会员归属与规则

| 责任 | 所在位置 |
| --- | --- |
| 套餐、价格、权益、退款规则、订单和 grant | backend/modules/memberships |
| EZFP 传输、验签、商户配置 | backend/modules/payments |
| 下单、支付生效、退款渠道与权益撤销编排 | backend/workflows/membership-purchase.ts |
| 金额、时长与权益使用事务 | memberships 与实际消费模块共用数据库事务 |
| 后台编辑 | apps/admin/src/components/memberships |
| 前台购买、续费与退款 | apps/web/src/components/memberships |
| 模型和迁移 | database/schema.prisma、database/migrations |

月度会员固定为 30 个 24 小时，季度、年度默认 90、365 天，可按已实现的后台规则配置。支付成功后生效，续费衔接现有期限，不自动扣费。价格、权益和退款参数按订单保存快照；后续改配置不追改已购买订单。

默认支付后 24 小时内可申请退款：未使用权益全额退款；使用过则按订单实付金额、实际时长和配置的扣费周期计算，向上取整到分，扣款不超过实付金额。渠道结果未确认时不能标记退款成功或撤销 grant；确认后仅撤销对应订单，并保持其他续费的有效时长。会员订单不得走金币到账或金币整单退款入口。

实际权益使用区分 RESERVED、CONSUMED、RELEASED：进行中的预占阻止退款，成功消费才计入扣费，失败释放后不算使用。公共免费额度优先使用，后台已给用户配置的更优惠倍率不会被会员覆盖。角色创建默认保持原来的无限行为；只有后台配置有限的公共数量上限后，会员更高的总上限才构成可购买的扩展权益，且仅超出公共额度的创建会记录会员消费。

## 运行与验证

根目录 `npm run dev` 启动 web、admin、api、worker。默认端口为 3010、3011、3012；worker 不监听 HTTP。独立应用也保留各自的开发、构建、启动命令。生产根入口 `npm start` 先检查数据库迁移一致性，再启动四个进程；不会自动替线上数据库迁移。

统一环境加载由 ops/runtime/environment.mjs 负责。SQLite 相对路径以 database/schema.prisma 为基准，并在进程启动前转成绝对地址。生产上传目录、备份目录应设置为发布目录之外的持久化路径。前台代理 `/api`、`/admin` 和 `/admin-assets`，后台静态资源不能与前台 `_next` 资源混用。独立后台浏览器来源通过 ADMIN_PUBLIC_ORIGIN 显式配置，不信任任意转发来源。构建与启动地址、环境和发布检查步骤见 runbook.md。

常驻后台任务仅从 worker 启动，故事状态任务通过同一任务注册表执行。手动执行入口沿用同一数据库租约，不再保留 Web/API 中的独立计时器。

阶段验收至少包含：依赖边界检查、完整类型检查、三个应用独立构建、真实 SQLite 集成测试、浏览器登录与栏目交互、后台配置与前台实际消费联动、支付与退款失败路径。源码检查或页面能打开，均不能代替业务验收。

会员前台已购流程的隔离浏览器验收命令为 `npm run test:e2e:membership`。该流程验证已支付订单、续费有效期、权益消费后的退款试算、取消确认和退款关闭失败路径；脚本中的 PAID 订单由会员领域服务在临时 SQLite 中构造，不代表真实商户付款、支付回调到账或渠道退款。

当前阶段状态以 architecture-plan.json 与实际验收输出为准。未通过完整验收前不发布、不启用真实收款，不将占位页面或跳过的测试计为完成。

服务器会员配置验收脚本为 tests/e2e/server-membership-config.mjs，需显式启用及专用最小权限账号。它会临时写入实际会员配置并在 finally 恢复，不应当作只读检查随意运行。2026-10-23 已在真实站点验证三种套餐价格、每日额外回复和聊天收费倍率的 UI/API/前台联动，见 validation-server-membership-config.json。该配置验收不等于真实支付或权益消费验收。

完整路由清单见 route-inventory.json，包含 URL、HTTP 方法、应用归属、源码入口和后端服务依赖。运行 `npm run architecture:routes` 从当前源码重新生成。此清单用于定位维护责任，不表示所有功能已经逐项实际操作验收。
