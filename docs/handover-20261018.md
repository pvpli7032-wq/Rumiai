### 一个必须知道的坑：release 根目录那份 ecosystem.config.js 是错的

`deploy/baota/ecosystem.config.js` 模板里写的是：

```js
const root = path.resolve(__dirname, '../..');
```

它**假定自己被放在 `<release>/deploy/baota/` 下**，这样 `../..` 才是发布目录。
但线上发布把这份文件复制到了 **release 根目录**（`<release>/ecosystem.config.js`），
于是 `../..` 解析成 `/www/wwwroot/khui-ai` —— 一个没有 app 的目录。
当前进程不是照它启的（实际 cwd 是发布目录），所以它一直没暴露问题。

**新发布时二选一**：
- 把配置文件放回 `<release>/deploy/baota/ecosystem.config.js` 再 `pm2 start`；或
- 直接按上面查到的真实参数启动：`cwd=<release>`、`script=<release>/scripts/start-production.mjs`。

无论哪种，启动后必须 `pm2 describe khui-ai` 确认 `exec cwd` 是新发布目录 ——
文档 `deploy/baota/README.md` 已经警告过"跨发布目录时不能仅依赖 startOrReload"。
